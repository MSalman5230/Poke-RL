# Team and lead selection rules

This section chooses which three of our six enter the battle, and which one leads. Live preview uses the prepared damage-and-Speed profiles in TS-11 to TS-16. The statistical selector remains the complete fallback and the provider for opponent party completion and hypothetical replacements. Opponent party assumptions belong to [opponent estimation, TS-08](build-prediction.md).

All rules below are implemented. This file describes current behavior; Markdown is documentation, and changing it alone does not change the bot.

## Current rules

| ID | Rule |
| --- | --- |
| TS-01 | Consider eligible, identified roster members and known opponent preview identities. Remove duplicate identities while preserving input order. At least three eligible members are required. Unidentified opponents stay unknown. |
| TS-02 | Use current/potential forms without changing observations. Compare our legal one-Mega configurations per trio; other stone holders stay base. Prepared preview treats Palafin's future form under TS-14; statistical callers preserve the existing Hero matchup hypothesis. Enemy forms come from the single usage-selected Mega hypothesis, with actual evolution taking precedence. Never credit several simultaneous Megas. |
| TS-03 | Statistical fallback, opponent-party completion and TS-09 use both directions of Smogon's Checks and Counters data at cutoff 1500. If either direction is absent or has no encounters, try 0 for both directions. If no usable pair exists, use zero and record missing coverage. |
| TS-04 | The statistical pair score is `(opponent KO/switch-out rate - our KO/switch-out rate) * n / (n + 20)`, where `n` is the smaller encounter count of the two directions. Higher favors us. This is a matchup index, not a win probability; small samples count less. |
| TS-05 | Evaluate every eligible trio, 20 when all six are available. Prepared preview ranks configurations under TS-13. Statistical callers take each trio's best pair score against each known opponent and average them, choosing a legal configuration by primary then backup coverage. Opponent-party completion uses only its highest-usage-probability Mega owner per trio. |
| TS-06 | Prepared preview uses the ordered score components in TS-13. Statistical ties use the average second-best matchup against each opponent. Exact remaining ties retain original roster/configuration order. |
| TS-07 | Choose one fixed lead using matchup scores averaged with normalized opposing family lead frequencies. Sum base/Mega lead frequencies within a common cutoff, preferring 1500 then 0. Prepared preview uses its opening matrix, including Zero-form Palafin and opposing Zero-form Palafin; statistical callers use their statistical matrix. A stone-holding lead must be the selected Mega owner while evolution is unused. Missing lead data uses the established zero/uniform fallback; ties retain roster order. |
| TS-09 | Automatic hypothetical replacements use legal living members' matchup ranks against the current opposing active, with stable party-order ties and no recursive search. Read actual current forms and remaining canMegaEvo availability from each serialized trial: a spent Mega cannot grant another member its potential form. Explicit candidates and BE-20 receivers override this automatic rule at their matched prompt; subsequent hazard/faint chains use TS-09. Probes and rollouts share the same resolver. |
| TS-10 | Save exact pair inputs/raw profiles/components, policy/cache/source identities, all eligible trios/configurations/assignments, ordered scores, opening matrix/lead weights, selected Mega owner/forms, assumptions and timings. TS-16 defines complete statistical fallback; exhausted deadlines or unavailable actions return no selection. |
| TS-11 | Precompute native full-HP one-on-one profiles for both directions of every saved-team variant against every complete default build available in the fixed metagame snapshot, including non-Mega and selected-Mega predictions. Node receives exact sets, forms, move/reference choices and seed `[1,2,3,4]`. It executes native entry/Mega effects and supplied attacks, returning HP/Speed and first/subsequent damage, self cost/healing, accuracy, priority, flinch and charge/recharge action costs. After a charged strike removes its native move marker, end only that completed two-turn lock through the native removal API, including zero-damage strikes. Preserve boosts, consumed items, defensive effects and recharge state for subsequent measurement. An unfinished charge at the two-action limit returns a profile error, never a partial cached profile. Damage uses the interpolated 92.5% multiplier with native truncation. Other non-accuracy random rolls use the midpoint. Accuracy is forced successful only to measure conditional-on-hit damage; its actual native chance is returned. Conditional moves receive supplied queued references, native pre-turn callbacks and an earlier reference attack where requested. Only the project worker/helper is extended; installed Showdown sources and live 32-trial mechanics stay untouched. |
| TS-12 | Python compares each fixed damaging attack against every modeled fixed opposing attack, choosing our best worst reply. Multiply measured damage/self cost by accuracy; apply first/subsequent profiles and native action costs. Order by priority, fractional priority and effective Speed; average both orders for an exact tie. Sucker Punch/Upper Hand cannot strike after the reply; reactive returns require acting later, and Focus Punch fails after a damaging earlier reply. Stop at a faint or 32 arithmetic exchanges. Advantage is `(our alive - their alive + our remaining HP fraction - their remaining HP fraction)/2`. Record both order outcomes and cap flags. A side with no modeled damaging attack receives a zero index with an explicit model limitation. This is a matchup estimate, not win probability; it omits setup/status-only plans, voluntary switches, semi-invulnerability during moves such as Fly, and evolving state beyond the measured subsequent profile. |
| TS-13 | A complete six-opponent preview with exactly one Mega hypothesis has ten enemy trios: that Mega plus each pair of the other five. Six with no Mega hypothesis (no member has a Mega form) have all twenty enemy trios. For every our-trio/configuration and enemy trio, examine all six one-to-one assignments and take the largest mean pair advantage. Rank our configurations/trios lexicographically by the minimum assignment score across the ten enemy trios, the mean assignment score, then backup coverage (the mean second-best answer to each enemy across those trios). This avoids assigning one member to several independent counters. It is a coverage heuristic and does not establish that favorable assignments can be forced in battle. |
| TS-14 | A Zero-to-Hero member may contribute either its initial-form matrix or a Hero hypothesis consistently within a trio configuration. The Hero hypothesis consumes one exposed opposing action before its Hero attacks become usable. If initial-form Palafin has usable Flip Turn, credit its cached Zero-form damage once during that activation action, using Flip Turn's own priority/Speed. Give no damage credit if it faints or flinches before moving, or the move cannot damage the target. Apply the chip to enemy HP without healing Palafin; net activation cost is our HP percentage lost minus enemy HP percentage lost (40% incoming and 10% chip gives 30%), including measured self costs. Each percentage uses that side's own maximum HP. The existing Hero defensive profile still estimates incoming damage; receiver and return switches remain abstract. This is never a free boost or an observed activation. A fixed lead is always evaluated in its actual initial form. A predicted opposing Palafin is evaluated conservatively over initial/Hero hypotheses, with the same activation cost; the opening matrix uses its initial form. |
| TS-15 | Build the reusable cache after a successful complete Box save and before matchmaking when the saved battle build changes. `prepare-preview` can also prepare it offline without tablet access. Fingerprint species/order, actual stats/stat points/nature, moves/PP, items, ability and form inputs; notes/read timestamps alone do not invalidate it. Version entries by catalog, prediction/input construction, fixed data and simulator/worker/helper identities. Raw profile version 3 includes Ditto copy contexts and corrected charging cycles; earlier profiles require a fresh pre-match build, not a score-only refresh. Cache raw profiles plus versioned Python race evaluations; cheap team/lead rankings are computed at preview. Persist a checksummed schema-2 gzip JSON bundle atomically under `runtime_data/state/preview_cache/`, using `runtime_data/tmp/` for temporary writes. Retain earlier bundles and all roster/history data. |
| TS-16 | Preview performs cache lookups and arithmetic only. A missing, corrupt, incompatible, unsupported or incomplete required profile rejects the whole profile selection; use the complete TS-03 to TS-07 statistical selector and record why. Never rank a partly completed matrix or refill a metagame cache against the preview clock. If no complete result fits the inclusive configured deadline, return no selection. Saved-result replay reruns the same Python ranking from recorded raw inputs/profiles without the cache; simulation replay reruns supplied profile requests with matching identities. JSON envelopes remain schema 2. |
| TS-17 | Compare each candidate directly against Ditto copying that candidate. Keep Ditto's predicted HP, item and ability, and supply copied attack options from Python. Coverage copies the selected already-active form; opening profiles use native Imposter timing before Mega Evolution and the actual Palafin starting form. A non-Imposter Ditto pays one opposing action before its copied attacks; this retains the preview model's fixed-profile defensive approximation. Native copying failure retains no copied attacks and records the limitation. Precompute both contexts before matchmaking and include native set, target/form and context in versioned cache inputs. Keep existing assignments, trio ranking and lead weighting; no dedicated-counter requirement. |
| TS-18 | A freshly observed numbered preview selection is an authoritative ordered prefix. Keep those members and their actual lead; apply the existing complete trio/configuration ranking only to legal completions containing that prefix. A selected stone-holding lead constrains the Mega owner under TS-07. Preserve the prefix in decision inputs and replay; never infer it from intended taps or unreadable counters. A fully observed committed trio needs reconciliation, not another selection. Unconstrained preview behavior is unchanged. |
