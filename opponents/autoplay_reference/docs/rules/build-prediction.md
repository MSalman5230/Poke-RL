# Opponent estimation rules

This section estimates one build per opponent (item, ability, nature, stat points and moves) and the unrevealed members of its three-member party. These are estimates assembled from usage statistics, not complete sets observed together. Our own build comes from the saved roster.

All rules below are implemented. This file describes current behavior; Markdown is documentation, and changing it alone does not change the bot.

## Current rules

| ID | Rule |
| --- | --- |
| BP-01 | Use the catalog to resolve species, forms, moves, items and abilities. Unknown species cannot receive a usable predicted build. Revealed moves, current items, abilities and forms take precedence over guesses. |
| BP-02 | Use the fixed September 2026 Champions BSS M-C data. Prefer cutoff 1500, falling back to 0 for compatible missing information. Both required chaos dataset files must be present and pass validation; a missing file blocks loading rather than silently inventing a build. |
| BP-03 | For unknown held items, use the one usage-selected Mega hypothesis under BP-10/11. Give its selected form the matching compatible stone; predict other unknown items from compatible non-Mega base-species usage, preferring 1500 before 0, highest weight then item-key order. Exclude predicted Choice items after more than one distinct native move in the same stint. Revealed items override hypotheses. Other members may legally hold observed stones even after evolution has been spent. |
| BP-04 | Keep current form separate from the predicted battle form. Only the selected available Mega owner receives a potential Mega matchup form; others use base forms until an actual evolution is observed. A predicted stone never activates live state or changes the current natural ability/stats. Palafin uses its existing Hero matchup hypothesis. |
| BP-05 | For ability, spread and move completion, prefer the held-stone usage form or predicted battle form, current form and base species, then other family Mega forms for compatible missing data. Within each form try compatible 1500 entries before 0, by descending weight then key. A current ability must be legal for the current form; a sole legal ability can complete missing data. |
| BP-06 | Choose one compatible nature/stat-point spread. Require six integer allocations from 0 to 32, totaling at most 66, and a known nature. Compute stats with the Champions catalog helpers. Missing valid spread data makes strict preparation incomplete; active battles may use BP-14. |
| BP-07 | Put revealed native moves into slots first, preserving their order. Complete to min(4, complete legal learnset size) distinct legal moves using usage data. If a species has fewer than four legal moves, include that complete catalog learnset; sparse usage data cannot complete an ordinary four-move species. More than four revealed native moves, an incompatible revealed native move, or insufficient legal moves makes the build incomplete. Predicted remaining PP is Champions maximum PP minus tracked expenditure, with a floor of zero. |
| BP-08 | Keep current item consumption/acquisition separate from the starting loadout. A known consumed item stays empty; a known acquired item overrides the old item. An unreadable acquired item remains unknown in facts; strict preparation is incomplete and active simulation may assume no item under BP-14. Temporary abilities retain their original ability separately. If that original is unknown, use an explicitly labeled natural-ability estimate or report the build incomplete. |
| BP-09 | Prediction never edits observed facts. Save each field's source, cutoff, usage weight/share and assumption, plus build errors. Retain damage/order evidence for future rules; the current predictor does not filter builds using that evidence. A build with errors is unavailable for battle simulation. |
| TS-08 | Keep every revealed member and the current active, then fill to three through shared coverage. A named opposing faint or ability/item announcement establishes party membership on its own; it does not independently change the active identity. Each candidate trio has one usage-selected Mega owner under BP-11; after selecting the trio, rebuild its scoped joint predictions so an excluded preview member cannot reserve its Mega slot. Only complete predictions are eligible; required incomplete members cause explicit failure, except fainted members, which receive the BP-14 placeholder. Recompute after new reveals. |
| BP-10 | Group a base species and all catalog-linked Mega forms for usage inference only. At one cutoff, calculate combined Mega usage / total base-plus-Mega usage. Prefer positive family usage at 1500, otherwise 0; never mix cutoff masses. Combine X/Y before calculating the Mega probability, then choose the most-used compatible Mega form. Keep raw usages, cutoff, probability, selected form and exclusions; forms still have distinct mechanics. |
| BP-11 | Assign at most one predicted Mega owner in the relevant preview/party scope. Choose the highest eligible family Mega probability even below 50%, then original preview/party order on ties. Observed stones/forms override usage; an active known stone holder with the slot available takes precedence. Actual evolution locks that side to its observed owner. No compatible positive-usage or observed-stone candidate means no invented Mega. Unknown non-owner items use base builds; observed extra stones are preserved. Ownership hypotheses never mark the side's evolution as spent. |
| BP-12 | A native move observed after a confirmed fight prompt for that same member/turn while the side's Mega was available records its first opportunity. Finalize at the observed round boundary; if no Mega form or stone was observed, infer a non-Mega build and reassign the hypothesis. This is an assumption based on bounded capture, not proof of its item. Switch-only/entry-only/unobserved opportunities and moves after the slot was spent do not trigger it. Later stone/form reveals override it. Retain prompt-frame/event/capture links, transfer or roll back identity-scoped evidence on Illusion correction, and never learn from simulated futures. |

| BP-13 | Keep native Ditto identity, HP, held item, natural ability and Transform PP separate from the observed copied snapshot. Copies retain target form, non-HP stats, types, ability, moves and copied PP caps at transformation time. Current copied PP/boost/ability/hit changes belong to the transformed stint and never add native moves. Switching restores native state. Confirmed opposing copies of our known roster can be hydrated directly; own unread copied UI slots remain unavailable. |

| BP-14 | Resolve temporary battle-form loadout families through catalog `battleOnly`/`baseSpecies`: current-form usage can use missing item/move data from its base. Keep current stats, types and abilities, revealed moves/PP and held-item changes separate. Permanent alternative forms and Ditto copies retain their own identities. During an active battle only, after usage/family lookup, fill missing item with no held item, ability with the first compatible catalog ability by ID, and spread with Serious/zero points/level 50. Retain revealed legal moves first, then complete with catalog-legal damaging moves ordered by power × accuracy × STAB and move-ID ties; remaining status slots prefer non-setup moves. Save each default and failed lookup as a simulation assumption. An observed Mega activation whose form BP-15 has not established predicts the most-used compatible candidate form under BP-10 usage (the first catalog form by ID without usage) with its implied stone and form ability; a pre-Evolution ability reveal is not reused. A fainted opponent whose build stays incomplete is hydrated at 0 HP from an observation-free base-form build, labelled as a placeholder with the replaced errors. Defaults never edit facts or erase incompatible reveals; other conflicts on living opponents route to BE-24. New-queue preparation and preview stay strict. |

| BP-15 | An opposing Mega is established by its stone message ("Charizardite Y is reacting") or by a message naming the form. When only a plain activation message ("Mega Charizard!") is understood, its catalog stone forms remain candidates, and one candidate becomes the observed form only when it alone is consistent with an observation: a post-activation announcement of that ability; our damaging move's super/extremely/not-very-effective message against its types (excluding type-variable moves, type-changing attacker abilities and overridden defender types); or a weather/terrain that began during the activation turn (start message, or a fight-screen field banner counter one turn below its total) and that the observed opposing move, our confirmed action and our active/entrant abilities cannot have set. Absent announcements and unread actions are not evidence. Unresolved activations use BP-14. |

## Maintaining this file

When a build rule is added, changed or removed, update its implementation and this file in the same change. Keep existing IDs stable, allocate a new ID for a new rule, and record the date, affected IDs and reason below. Describe implemented behavior here; label proposed ideas explicitly until they are implemented. Update relevant regression coverage when behavior changes.
